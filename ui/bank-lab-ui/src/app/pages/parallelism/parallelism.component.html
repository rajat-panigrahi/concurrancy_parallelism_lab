Parallelism lab

Two ways to make things faster, and they are not interchangeable. Parallelism uses more cores to finish CPU work sooner. Concurrency overlaps waiting, using no extra cores at all.

The rule

async is for waiting. Parallel is for working. If the operation waits on I/O, the CPU has nothing to do — more threads just means more idle threads. If the operation computes, async achieves nothing; there is no waiting to overlap.

The surprise

Parallelising with a lock per item is often slower than one core — measured at 11× slower. Four cores queueing at one door. Partition the work and aggregate once at the end instead.
