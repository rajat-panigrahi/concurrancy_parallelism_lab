Which one, when

SituationUseWhy
Conflicts rare, short transactions, web APIoptimisticNo locks across requests; cost is an occasional retry
Hot row everyone writespessimisticOptimistic would retry-storm: N× work for 1× throughput
User think time (an edit form open for minutes)optimisticNever hold a DB lock across a coffee break
Redoing the work has side effectspessimisticA retry means doing it twice — sometimes a second email
Single process, in-memory statelockCheapest — and dies the moment you add an instance
Must serialise non-row work across instancesdistributed-lockProcess memory isn’t shared
The logic fits in one SQL statementnoneSET balance = balance - 40 WHERE balance >= 40 — no gap, no coordination
